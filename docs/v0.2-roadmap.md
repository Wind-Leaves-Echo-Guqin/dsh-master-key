# v0.2 路线图与未竟事项

## 已实现（v0.2.0）

- **out-of-process 协议包**：MCP stdio 桥。插件在 package.json 声明
  `dsh.mcp.servers`，适配器完成 MCP 握手（initialize/tools list/tools call），
  把 server 的工具以 `mcp_<别名>_<工具名>` 注册进 ctx.tools。
  测试：L4 三件套（认领/真实子进程往返/握手失败 fail-open）+ 真内核探针（0.2.0-rc.2 与 0.1.1-rc.2）。
  已知边界：仅支持 stdio 传输；inputSchema 只映射 type/description/required；
  server 崩溃后的自动重启策略未做（当前 fail-open 跳过）。

## 未实现（按优先级）

### 1. eac-shell-bridge 协议包（EAC v6 window.dshDesktop）
**为什么没做**：EAC v6.0.0-beta 未在本机安装，且 `window.dshDesktop` 是客户端半接口，
无法在会话内诚实测试。协议面已完整考据（见 protocol-chronicle.md §5.1-5.3）：
- `window.dshDesktop` protocolVersion 1：plugins{list/add/remove/update}、updates、boot{start/stop/state}、windowControls、`_call/_send/_onNotify/_onReady`
- 能力桩语义 `{ok:false, unavailable:true, capability, reason}`（本项目的降级信封即源于此）
- 退役语义：JSON-RPC -32601 / HTTP 404
- 传输：L1↔L2 stdio JSON-RPC；桌面窗↔sidecar WS JSON-RPC（127.0.0.1:19873）
- 分发账本：`.sync/plugin-distribution.json` + `plugin-inventory-history.json` + `.dshpack`
- 皮肤协议：skin.json + `--eac-shell-*` token + `/skin/<file>` 白名单路由
**做的时候**：装 EAC v6 → 变体描述加 windowFlag 检测 → pack 的 probeHost 检查
`window.dshDesktop?.protocolVersion === 1` → 对接账本只读 + 能力桩透传。
